# Архитектура MVP — Обменник «ЦАРЬ»

Цели MVP
- Пользователь может отправить токены 👑 ЦАРЬ в одну из двух сетей: TON или BSC (BEP-20).
- Система фиксирует депозит, создаёт ордер на продажу и рассчитывает сумму в рублях по курсу (спот).
- Администратор может просмотреть ордер, верифицировать и запустить выплату на карту клиента (через эквайринг/SBP) или завершить через Binance P2P (ручной/полуавтомат).

Компоненты
1. Backend (Node.js + Express)
   - API: создание ордера, статус ордера, webhook для нод/мониторов
   - DB: Postgres (orders, users, deposits, payouts, logs)
   - Workers: watchTon, watchBsc — следят за входящими транзакциями
   - Payout engine (пока: admin-triggered)

2. Blockchain monitors
   - TON monitor: прослушивает адреса депозитов (ton-client или tonweb)
   - BSC monitor: ethers.js для BSC (RPC)

3. Платежные интеграции
   - Эквайринг / SBP: требуется контракт с эквайером (Tinkoff, CloudPayments, PayMaster и т.д.) для payouts на карту.
   - Binance P2P: автоматизация ограничена (официального API для P2P нет). Рекомендуется использовать ручной/полуавтоматический workflow: оператор продаёт RUB через P2P и отмечает выплату в системе.

4. Админ-панель
   - Просмотр новых ордеров, KYC/AML-статус, кнопка "Выплатить" и лог транзакций.

Безопасность & Compliance
- KYC/AML обязательны для операций вывода фиатных средств.
- Хранение PRIVATE KEYS: используйте HSM/Секреты (Vault, Cloud KMS) — не храните в Git.
- Логи транзакций и мониторинг аномалий.

Требуемые внешние данные для запуска
- Адреса контрактов токена ЦАРЬ (TON и BSC)
- RPC узлы: TON RPC, BSC RPC
- Адреса депозитов (или схема генерации адресов per-user)
- Аккаунты/ключи для кошельков, используемых для контроля депозитов
- Доступ к эквайеру/банку или процедура ручной выплаты
- KYC провайдер (опционально) или инструкция для админа
